Altius in the closed-loop pattern

The reference loop is: connect data → organize it in an Ontology → run models → present actions → write decisions back → learn continuously. Altius holds the two hardest ends of that loop and breaks in exactly two places.

built partial absent governance perimeter

The two breaks

Everything else in the loop is either built or deliberately out of scope. These two edges are what stop it from closing.

BREAK 1 No model layer — but the edge is inverted, not missing

There is no model registry, no inference runtime, no LLM gateway, no embeddings. Nothing in Altius can run a forecast or a simulation, and there is no what-if branching to run one against — every action writes live.

What landed instead is packages/mcp-server: Streamable HTTP + JSON-RPC 2.0 mounted at /mcp when a pack declares the mcp capability, exposing governed actions as MCP tools. So the binding the pattern demands — models bound to Ontology objects, usable inside real workflows — is achieved by exposure rather than hosting. An external model is just another OIDC principal running the same 8-stage pipeline: same ReBAC, same consent, same audit. For a headless platform that is the stronger position; it is also the cheaper one.

What is still genuinely missing for the loop is not the model — it is capturing suggestion → decision → outcome as first-class data.

BREAK 2 No feedback consumer — the data is already there

Unusually, the hard half is done. Every action is audited including denials, every object and link change emits a CloudEvent, *_history tables hold the full state-transition record, and sync now exports processed/failed/staleness metrics. That is a high-quality event log for learning.

Nothing reads it. There is no aggregation, no monitoring rule, no retraining trigger, and no general scheduler — the SyncScheduler that just landed drives data intake only; it is not an Automate-equivalent. This is the same missing component already sitting at #2 on the roadmap: a trigger engine consuming the event bus. Closing it closes the loop.

Stage by stage

Ingest & Connect

partial · just upgraded

packages/sync · JdbcConnector · mapping DSL · CdcConsumer · ConflictResolver · SyncScheduler (a5705b9)

The driver loop that made this an inert library now exists, opt-in via SYNC_SCHEDULER_ENABLED, with per-field conflict resolution and bounded ticks. Missing: push intake (pull-only — no Listeners equivalent), no Debezium/Kafka consumer, REST connector is a stub, lineage is in-memory only. Sync writes bypass the action pipeline by design, so ingest is outside the governed write path.

Ontology

built · strongest layer

packages/odl → one ParsedSchema IR drives GraphQL SDL · OpenFGA model · REST routes · OpenAPI/AsyncAPI · action-manifest validation · MCP tool descriptors

This is the "common thread" property, mechanically real: every artifact is a pure function of one schema, so data, logic, actions and security cannot drift apart. Objects, links, actions, object sets, temporal history, and a schema registry that classifies changes SAFE/COMPATIBLE/BREAKING and gates breaking applies behind a migration plan. Interfaces are being operationalized right now. Missing: branching, media, time series, struct types, geo semantics.

Apps & Workflows

absent · by design

Headless is the stance, not an oversight — the substrate a UI needs is exposed: generated GraphQL/REST, FGA-checked subscriptions, and JSON-Schema action descriptors from which forms auto-generate. The real backend gap hiding here is scenarios: no staging, no what-if, no comparison. The SPI transaction contract and history tables are the hooks, but nothing stages an un-applied change today.

Operator decisions → Write-back

built · second-strongest

packages/actions · validate → authorise → consent → preconditions → execute → side-effects → audit → emit

Transactional effects with ROLLBACK_ALL compensation, webhook side-effects out to source systems, append-only audit now enforced at the database (trigger + REVOKE), CloudEvents emitted post-commit. Asymmetry worth naming: sync is one-way in; the only path back out to a system of record is a webhook (POST-only, no managed credentials or OAuth).

Governance

built · cross-cutting

The reference diagram draws governance as dotted lines to each layer. In Altius it is a single pipeline every surface funnels through — one insertion point, not five — which is why adding a new control lands everywhere at once. Missing: markings (mandatory controls), durable lineage, and row-level security (tenancy is app-layer only).

The cheapest way to close the loop is a domain pack, not a platform feature

The feedback stage does not need new platform machinery to start. Because the Ontology is the common thread, Suggestion, Decision and Outcome can be modeled as ODL object types with their own actions — shipped as a pack, no core change. The audit trail and CloudEvents give capture for free; MCP lets an external model write suggestions in through the same governed pipeline a human uses; the *_history tables record what actually happened next.

That turns the loop from a platform project into pack content, and leaves exactly one platform-level dependency: the trigger engine that reads the event bus and acts on it.
